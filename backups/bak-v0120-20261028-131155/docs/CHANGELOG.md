## v0.11.0 — 2026-10-28

### 新增

- **网页版增量同步**：设置页新增「增量同步（与终端版共用记录）」卡片，预检 → 上传改动 / 下载远端改动三种操作。
  - 接口：`GET /api/sync/info`、`POST /api/sync/plan|push|pull`（`gui/server.py`）
  - 只传改动的文件（`state.json`、题库各一个压缩包）；同步状态就是终端版那份 `quiz_parser.data/cloud_sync.json`
  - 冲突以本地为准；本地删掉的文件同步删远端，本地被远端删掉的文件移到 `backups/cloud-deleted/`
  - 预检只读远端清单，不产生任何写请求；同一时刻只允许一个同步在跑
- **冲突策略可配**：远端已有不同内容时可选 每次问 / 直接覆盖 / 跳过；勾「不再提示」会记住，设置页可改回；自动备份按策略执行不弹窗。
- **压缩上传**：整份备份改成 `.json.gz`（26.6 MB → 5.66 MB），恢复时自动解压并校验哈希。
- **内容寻址文件名**：远端文件改名为 `shiroha-web-<12位内容哈希>.json[.gz]`；上传前先 `HEAD` 问一句，已有同内容就跳过（换设备也有效）。
- **参考文档**：`docs/REFERENCE-webdav-sync.md`（Remotely Save / rclone / Unison / Syncthing 的算法出处、许可证与可借鉴点）。

### 更新

- 界面与提示里的「自动同步」统一改叫「自动备份」——它只上传不双向同步，名字与行为对齐。
- 远端备份列表兼容两种命名：新格式显示内容指纹，旧格式标「旧格式」。

### 修复

- 上传完成后写回配置时会把刚「记住」的冲突策略覆盖回旧值（赋值顺序写反）。
- 增量同步在 `.xz` / `.7z` 两种压缩格式间切换时，远端会残留两份；现在同一文件只保留一种后缀。
- 拉取时优先找 `.7z`、找不到再找 `.xz` 的写法会取到旧包；改为按 manifest 里的哈希校验后取正确的那份。

## v0.10.7 — 2026-10-27
### 新增
- WebDAV 面板新增「开启自动同步」：勾选后，GUI 每次保存数据（题库/错题/收藏/记录/设置）都会在 20 秒内自动上传一份完整备份；内容与上次上传完全一致时自动跳过，不产生重复文件。
- 自动同步状态在设置页可见（等待中 / 上传中 / 完成文件名 / 失败原因），并记录「上次自动同步时间 + 结果」到本地配置。
- 手动上传与自动同步共用同一条代理通道与 `latest.json` 清单，远端列表会同时显示两类备份。

### 说明
- 自动同步只上传、不自动删除远端文件，也不会自动覆盖本机数据；恢复仍需手动确认。
- 自动同步需要已保存可用的 WebDAV 密码；浏览器离线或未填写密码时自动跳过并给出提示。

## v0.8.9 — 2026-10-27 · 解压优先 7-Zip

**更新**
- 解压默认 `auto`：`.7z` 走 7-Zip，`.xz` 走标准库（各自最快），失败自动回退

**说明**
