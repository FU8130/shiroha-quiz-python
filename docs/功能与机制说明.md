# Shiroha Quiz 功能与机制说明（人话版）

> 用途：以后想调整任何东西，先看这份。它描述「现在是什么样、为什么这样」，
> 不描述「应该是什么样」——想要的区别记在 `docs/待决策-第三轮.md` 里。
> 对应版本：0.12.1（2026-10-28）。项目目录随 U 盘盘符变化，本文用「项目目录」代指。

---

## 1. 一句话说清这是什么

一个本地刷题工具，**同一份数据、两个入口**：

- **终端版**（`quiz.py` / `Start-Quiz.bat`）：键盘流，适合坐在电脑前连续刷。
- **网页版**（`quiz.py --web` / `Start-Quiz-GUI.bat`，默认 http://127.0.0.1:8799）：能用鼠标、能上手机、能局域网访问。

两边不是两个程序，是同一个程序的两张脸：错题、收藏、进度、历史、复习计划都存在同一堆文件里，改哪边另一边都能看见。

**零第三方依赖**：只用 Python 标准库。想压缩、想解压、想传云端，都靠标准库 + 可选的内置 `tools/7zr.exe`。

**数据不散落**：不写 `%APPDATA%`、不写注册表、不写用户目录，所有东西都在项目目录里，拔盘即走。

## 2. 东西都放在哪

```
项目目录/
├── quiz.py                 入口（终端版 + 网页版）
├── banks/                  题库，一题一库一个 .csv
├── config/                 配置与密码（可跟项目一起带走）
│   ├── config.json         全部设置
│   ├── cloud.secret        云密码（终端版与网页版共用）
│   ├── bank_counts.json    每个库的题数缓存
│   ├── cloud_sync.json     增量同步的“上次同步对照表”
│   ├── sync_device.json    本机标识
│   └── gui_kv.json         网页版偏好（夜间模式等）
├── quiz_parser.data/       你的答题数据
│   ├── state.json          错题、收藏、进度、复习卡片（核心）
│   ├── history.json        每次练习/考试的记录
│   └── cloud_sync.log      同步日志
├── backups/                备份（项目备份、恢复前自动副本、云端删除的文件）
├── tools/7zr.exe           可选的内置 7-Zip 独立版
├── plugins/                插件（可选）
└── docs/                   文档
```

判断依据：**配置是“怎么跑”，数据是“你做过什么”**。前者放 `config/`，后者放 `quiz_parser.data/`。

## 3. 答一道题，背后发生了什么

这是整个项目最值得先搞懂的一条线，改任何功能前都该知道它。

### 终端版

1. 你按 `A` / `B` / `1` / `2`，`KeyReader` 读到键。
2. `_ask_question` 把键翻译成选项字母，校验（只认当前题存在的选项、单选限一个、多选去重）。
3. 判分，更新这一库的状态：
   - 错了 → 进错题本、错题计数 +1、状态记“未掌握”；
   - 对了 → 若在错题本里，更新掌握状态；
   - 收藏（`F2`）、标记（`F4`）、跳题（`#12`）、上下题（`[` `]`）。
4. `save_state()`：把这一库的错题/收藏/进度/复习卡片写进 `state.json`。
   **写法是原子的**：先写同目录 `.tmp` → fsync → `os.replace`，写之前留 `.bak`，启动时若发现 `.writing` 残留就用备份回滚。
5. `_auto_data_sync()`：把 `state.json` + `history.json` 打成「数据包」传到云端（20 秒内最多一次，失败静默，不打断答题）。
6. 一轮结束：写一条 `history.json` 记录；退出练习时再触发一次增量同步（10 分钟节流）。

### 网页版

1. 点选项 → `app.js` 本地判分，界面立刻出结果（不等服务器）。
2. `bridge.js` 的 `scheduleState()` 300 毫秒后把状态 `POST /api/state` → 服务器落盘（同样原子写）。
3. 落盘成功后回调 `window.__shirohaAfterStateSave()`。
4. `app.js` 等 1.5 秒（防抖），调 `/api/data/backup` 把数据包传云端；内容没变时服务器只发一个 HEAD 就返回。

**关键设计**：判分在前端、落盘在服务端、备份异步。所以断网也能继续做题，重连后状态会补传。

## 4. 题库：导入、识别、管理

- **格式**：`banks/*.csv`（也支持导入 JSON / xlsx 转出的 CSV）。题库名就是文件名，文件名变了内部哈希不变，数据跟着走。
- **入库流程**：选文件 → 解析（`quiz_parser/`）→ 预览（识别了多少题、哪几题有问题）→ 确认写盘 → 刷新计数缓存 `bank_counts.json`。
- **AI 识别与解析**（网页版设置里有单独的 API Key）：用于把图片/文本题库变成结构化题目，以及给单题生成解析草稿。**AI 只生成草稿**，替换已有解析要你二次确认。
- **题库管理**：改名、删除、二次编辑（题干/选项/答案/解析）、批量导出、合并导入。
- **删除是很重的操作**：走 `danger_confirm`（两次确认）。
- **同名/同内容**：导入时按内容哈希判重，重复内容不会被重复登记。

**身份机制（重要）**：每个题库算一个 `content_hash`，`state.json` 里按“哈希 → 数据”存一份归属信息。所以题库改名、移动路径后，错题/收藏/进度会自动继承过来。换盘符同理。

## 5. 练习与考试

### 练习

- **范围**：全部 / 未做过 / 只练错题 / 收藏 / 指定章节或标签。
- **顺序**：顺序 / 随机 / 按错题次数优先。
- **模式**：单题一屏；答完可设「自动下一题 / 智能暂停 / 每题都停」。
- **界面元素**（终端版）：
  - 状态条：`█ 答对` `▓ 答错` `· 未答`，当前题用 `◆`（网页版用方括号）；超过 60 题时按段合并，格内有错标红。
  - 头部：`已答 N`、`✅/❌/⭐` 计数。
  - 状态行常驻：`[★ ✎] >`（★ 收藏、✎ 标记）。
- **回看**：按 `[` 回到上一题，会显示「你的答案：X」，选项前加 `▸`。
- **答题卡**：`?` 打开，能看到每题状态并跳转。
- **输入规则**：单选按新字母直接替换；多选**再按一次已选字母即取消**（`A A B → B`），与网页版一致。

### 考试

- 固定题量 + 时间上限，倒计时按秒刷新（`⏱ mm:ss`），时间到**直接交卷**（不再问“要不要交”）。
- 交卷后出分、错题入库、写一条历史记录。
- 中途退出会提示“当前作答不会评分保存”。

### 间隔复习（只有终端版有入口）

- 算法：**FSRS-6**（21 个参数，Anki 25.x 同款），评级 1=重来 / 2=困难 / 3=一般 / 4=容易。
- 参数：`config.json → srs`（每日新卡、每日复习上限、学习步长、Leech 阈值、一天从几点算起、随机抖动、提前学习窗口）。
- 复习管理：逐卡记录、单卡重置/暂停、30 天到期预测、撤销。
- 记录：`srs_log` 最多保留 5000 条。

## 6. 错题、收藏、搜索、统计、历史

| 功能 | 终端 | 网页 | 说明 |
|---|---|---|---|
| 错题回顾 | ✅ 菜单 4 | ✅ | 按错题次数排序，有筛选 |
| 收藏回顾 | ✅ 菜单 5 | ✅ | `F2` 收藏 |
| 搜索题目 | ✅ 菜单 9 | ❌ | 按关键词找题 |
| 统计总览 | ✅ 菜单 10 | ✅ 部分 | 正确率、趋势、薄弱点 |
| 历史战绩 | ✅ 菜单 7 | ✅ | 每次练习/考试的明细 |
| 清空数据 | ✅ 二次确认 | ✅ confirm | 错题/记录/收藏分别清 |

**统计口径**：`已答` 只算“答对 + 答错”，跳过不算；正确率 = 答对 / (答对 + 答错)。

## 7. 备份与同步（三层，别混）

| 层 | 内容 | 大小 | 什么时候发生 | 文件名 |
|---|---|---|---|---|
| 项目备份 | 整个项目（排除密码、缓存、旧备份） | ~2 MB | 手动，或菜单里的整包备份 | `project_*.tar.xz` |
| 整包快照 | 全部数据 + 题库 | 26.6 MB → 压后 5.7 MB | 手动上传；自动模式下练习/考试结束时补一份 | `shiroha-web-<12位哈希>.json.gz` |
| 数据包 | 只有 `state.json` + `history.json` | 几 KB | **每次保存后 1.5 秒**（网页）/ 20 秒节流（终端） | `shiroha-data-<12位哈希>.json.gz` |

**为什么这样分**：答题产生的是“你的数据”，几 KB；题库是“静态内容”，十几 MB。把两者拆开，日常保存几乎不耗流量，需要整包时再整包。

**内容寻址**：文件名里的哈希 = 内容指纹。传之前先 HEAD 问一句“有吗”，有就跳过。所以重复保存 = 0 上传，换设备也不会重传。

**增量同步**（另一条线，面向题库和状态文件）：`manifest.json` 记每个文件的 sha256，只传变化的文件；删除用“墓碑”（`deleted` 表，保留 180 天），不会误删另一台设备的新文件。

**冲突策略**：`ask`（每次问，默认选覆盖）/ `overwrite` / `skip`，可“记住选择”，在设置页随时改。

**自动备份的三种方式**：
- `auto`（默认）：每次保存传数据包；练习/考试结束时若距上次整包 ≥10 分钟，补一份整包快照。
- `incremental`：只传数据包，从不自动整包。
- `snapshot`：每次都传整包（约 5.7 MB/次）。

**失败时**：自动模式永远静默，不弹窗、不打断答题，结果只写在设置页的状态行里（这是已知短板，见待决策）。

## 8. 云端与局域网

- **支持的云**：任何 WebDAV（坚果云、Nextcloud、Alist 等）。地址、账号、密码填在设置页；密码存 `config/cloud.secret`，终端版与网页版**共用同一份**。
- **网页版怎么绕跨域**：浏览器不直接连 WebDAV，而是走本地服务器 `/api/webdav/proxy` 转发。
- **局域网访问**：默认开启（`config.json → ui.lan`）。启动时打印 `http://<内网IP>:8799`，同一 WiFi 的手机可打开。
- **口令**：`--token <字符串>` 才启用；启用后首次访问要带 `?k=<口令>`，服务器发 30 天有效的 Cookie。
- **没设口令时**：只打印一行警告，不阻止访问（已知风险，见待决策）。
- **防火墙**：不自动改，只在启动时打印需要的 `netsh` 命令。

## 9. 插件

- 放一个 `.py` 到 `plugins/`，实现 `register(app, menu)` 即可。
- 能做的：往主菜单加一项、拿到 `app`（可读配置、可调 `app.save_state()`）。
- 不能做的：替换核心流程（答题、判分、同步）。
- 版本校验：`PLUGIN_API = 1`，不匹配就跳过并记日志。

## 11. 安全与容错（已经做了的）

- **原子写**：所有 JSON 都是 `.tmp → fsync → replace`，断电不会写出半个文件。
- **启动回滚**：发现 `.writing` 残留，自动用 `.bak` 恢复并提示。
- **崩溃日志**：`crash.log`，1 MB 轮转 ×5。
- **危险操作双确认**：清空本地、清远端、删题、清错题、清记录（终端版）；网页版用 confirm。
- **密码不外传**：同步时密码只用于 WebDAV 认证，不写进任何备份包。
- **备份前自动留档**：恢复数据包/快照前，先把本地旧文件复制到 `backups/data-before-restore-*`。

## 12. 已知差异与短板（不是 bug，是取舍）

1. 网页版没有「搜索题目 / 间隔复习 / 复习管理」三个入口（终端版有）。
2. 首页「待复习错题」这个数字实际显示的是错题数，且网页版没有复习入口可点。
3. 数据包目前**只有上传，没有恢复界面**（服务端接口有，前端没做）。
4. 自动备份失败只在设置页状态行提示。
5. 局域网默认开、默认无口令。
6. `history.json` 只增不减。
7. 网页标题还是旧的 “V38” 字样。

**要动这些，先看 `docs/待决策-第三轮.md`。**
